# uk-card-site

QR landing site for UK's business card. Pure static HTML/CSS/JS — no build step, no framework.
Open `index.html` directly or serve the folder with any static host (GitHub Pages, Netlify, university hosting).

## Edit content here (nothing else needs to change)

| File | What it controls |
|---|---|
| `data/profile.js` | name, affiliation, labs, hero sentence and bullet points, "Now" badge, email, home-page photos, calendar embed URL, Google Scholar link, `siteUrl` (QR + link previews) |
| `data/materials.js` | the 14 materials on the periodic table (one entry each; elements, family, dopants, blurb) |
| `data/measurements.js` | measurement/capability list; `featured: true` = home tile + card back; `service: true` = "Available on request" badge |
| `data/focus.js` | Focus one-liner and the Focus page text (light markdown) |
| `data/publications.js` | paper list — generated by `scripts/fetch_publications.py` from a verified DOI list; `image`/`imageCredit`/`featured`/hand-written `abstract` are kept across refreshes |
| `assets/img/` | `portrait.jpg` (square crop) and `portrait-full.jpg`; `pubs/` holds paper figures — CC BY only, credit in `imageCredit` |
| `contact.vcf` | the **Save contact** card — name, role, department, email, site, embedded photo. Hand-written; keep it in step with `data/profile.js` |
| `assets/img/og.jpg` | 1200×630 link-preview card (og tags on every page point at it) |
| `assets/img/qr-site.svg` | the QR the footer shows; vector, so the same file prints on the paper card. Regenerate with `python3 scripts/make_qr.py` |

## Pages

`index.html` (hero + bento) · `schedule.html` · `measurements.html` · `publications.html` · `focus.html` · `materials.html` (periodic table; deep-link with `materials.html#Nb3Sn`) · `ppms.html` (live helium-recondenser readout, `noindex`).

Every page carries a description, canonical URL and og/twitter preview tags, and a footer **Show QR** link — `#qr` on any page opens the QR sheet straight away (bookmark `/#qr` to turn the phone into the card). Without JavaScript the same link opens `assets/img/qr-site.svg` directly.

## Design rules

Near-black background, one violet→orange glow, glass tiles, faint noise. Colour appears in exactly one place per screen (the Focus tile, or the selected material). See `assets/css/site.css` tokens.

## Publications

Google Scholar blocks automated access and has no API, so it is only the profile link. The DOI list in `scripts/fetch_publications.py` is the source of truth (11 peer-reviewed papers, verified 2026-09-22). Add a paper with `python3 scripts/fetch_publications.py --add <DOI>`. Figures: only CC BY articles are shown with a figure by default; closed-access papers show abstract + DOI until an author-owned image is supplied.

## RSM Studio

`rsm.html` computes substrate and film reciprocal-space sections from two local CIFs.
It uses the existing Phase Viewer geometry helpers and shared lab-code endpoint;
the strict RSM CIF reader is isolated, so the existing Phase Viewer parser is unchanged.
The model, conventions and limitations are documented in [docs/RSM_MODEL.md](docs/RSM_MODEL.md).

The 2D map uses Gaussian peaks. The separate thickness panel shows an ideal continuous-slab
`sinc²` profile; it is not a 2D fringe simulation. Numerical checks use analytical or synthetic
references, not measured RSM intensities. Uploaded CIFs, sessions and calculations stay local.
The only application network write is the shared-code check using `action=xrdcheck`.
As with the other lab tools, the code gate does not make the static application files private.

### Local preview and verification

```sh
python3 scripts/serve_rsm_preview.py --port 8767
# Open http://127.0.0.1:8767/rsm.html; local test code: rsm-local-test
node scripts/test_rsm_cif.cjs
node scripts/test_rsm_core.cjs
node scripts/test_rsm_integration.cjs
node scripts/test_rsm_page.mjs
```

The preview server substitutes a loopback code-check endpoint. It never validates a code
against the production service. Browser tests use an isolated Chrome profile and block external
hosts. `data/rsm.js` controls whether the shared-code form is shown; production keeps it enabled.
Only an acceptance flag is saved in session storage. **End session** clears it and reloads the app.
Use **설정 저장** before leaving to preserve both CIF texts, chosen blocks and controls.

IT92 coefficients are shipped as a generated, attributed table. Reproduction requires
`gemmi==0.7.5` and `python3 scripts/generate_rsm_factors.py --check`; the browser does not need Python.
The software listing lives in `data/software.js`.

## XRD Studio shared lab code

`xrd-studio.html` asks for the shared lab code in Korean or English (`?lang=ko` or
`?lang=en`). Apps Script checks `XRD_CODE` and answers `{ok:true}` on success. The page then
loads the ordinary static app at `assets/xrd/` or `assets/xrd/en/` in an iframe.

**Anyone who knows the app URL can open it directly without entering the code.** The code
is not stored in public JavaScript, but the app files are public. `noindex, nofollow` asks
search engines not to list the pages; it does not prevent direct access.

### Deploy

1. In the existing inventory Apps Script project's **Project Settings → Script properties**,
   set **`XRD_CODE`** to the shared lab code. Keep it distinct from `EDIT_CODE` and `PUSH_CODE`.
   This is the only new property required. Do not put the code in the site's files.
2. Copy `scripts/apps-script/he-inventory.gs` into that project and deploy a **new version**
   of the existing web app. Keep its current spreadsheet, execution/access settings, and
   `/exec` URL in `data/ppms.js`. The endpoint now accepts a form POST with `action=xrdcheck`.
3. Build the app from the `xrd-studio` checkout into this site's `assets/xrd/` directory:

   ```sh
   python3 scripts/build_web.py --output ../uk-card-site/assets/xrd
   ```

   Adjust the sibling checkout path if using worktrees. Commit all twelve generated files
   together with the website change. Future app updates use this same build command.
4. After the updated Apps Script and app files are deployed, set `data/xrd.js` to
   `enabled: true`. This single switch controls the Software icon link, Open in browser
   button, and code form. Disabled mode makes no code-check request. The direct app URL
   remains usable regardless of this switch.
5. On the live HTTPS site, check a correct code, an incorrect code, and a complete fit.
   Confirm the existing inventory and telemetry still work. Five-failure tests use the
   local harness so they do not interrupt lab users.

Live Google redirect/CORS behavior still needs the final check after Apps Script deployment.
The local browser test executes the actual Apps Script handlers using mocked Google services;
it never contacts the production endpoint. GET `?action=xrdcheck` returns a POST-only message
without checking a code. The retired prototype endpoint rejects requests without touching
inventory or collector counters.

### Sessions and code attempts

The page remembers only `xrd-studio-open = "1"` in `sessionStorage`. It clears the input after
submission and never stores the lab code. Reloading this tab opens a fresh app session without
another code check. **End session** removes the flag and unloads the app and fitting worker.
Save settings before reloading, switching language, or ending the session to keep your work.
A remembered tab is not rechecked when the shared code changes.

Five incorrect codes pause code checks for everyone for ten minutes, including correct-code
attempts during that interval. The durable XRD counter is separate from inventory and collector
counters. This pause does not affect direct app URLs or tabs that already remember acceptance.

### Local verification

```sh
node --test scripts/apps-script/test_xrd_auth.cjs
node scripts/test_xrd_gate.mjs --xrd-root ../xrd-studio-gpt
```

The browser test uses its own local server and Chrome profile. `--chrome PATH` selects another
Chrome binary. Numerical parity tests belong to the `xrd-studio` checkout. To update the shipped
app, edit that source and rebuild; do not edit generated `assets/xrd/` files by hand.
